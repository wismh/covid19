# GDD — COVID-19: The Beginning

> Реконструйований Game Design Document за результатами аналізу коду та наявних матеріалів (`readme.md`, `Docs/*.gif`). Оригінального написаного GDD в проєкті не існувало — цей документ відновлює дизайн з фактичної реалізації, зроблену за 96 годин на GMTK Game Jam 2024.

## 1. Огляд

| | |
|---|---|
| **Назва** | COVID-19: The Beginning |
| **Джем** | GMTK Game Jam 2024, тема **"Built to Scale"** |
| **Тривалість розробки** | 96 годин |
| **Команда** | 6 осіб — 2 художники (Dinobarrys, EarthMaster), 1 музикант (Generall Romell), 3 Unity-розробники (NeutrinoZh, Sanyo4ek, Hea7en) |
| **Платформа** | WebGL (itch.io), Windows standalone |
| **Жанр** | Top-down twin-stick shooter / arena survival з RPG-прогресією (на кшталт Vampire Survivors) |
| **Посилання** | [itch.io: covid-19-the-beginning](https://neutrinozh.itch.io/covid-19-the-beginning) |

**Піч:** ти — нанобот-лікар, який заходить всередину заражених вірусом клітин, щоб вилікувати їх. Але віруси мутували і можуть чинити опір.

## 2. Реалізація теми "Built to Scale"

Тема джему реалізована буквально — через механіку **перемикання масштабу світу**, керовану `WorldState` (`MICRO_WORLD` / `MACRO_WORLD`):

- **MACRO_WORLD** — гравець літає у відкритому космосі/просторі в нормальному масштабі (`localScale = 1`), полює на вільних вірусів, які намагаються заразити дрейфуючі клітини.
- **MICRO_WORLD** — натискання **E** біля хворої клітини зменшує гравця до `localScale = 0.3`, швидкість переміщення падає до **1% від макро-швидкості** (`SpeedScale: 1 → 0.01`), камера наближується (orthographic size 5 → 1.9), гравець фізично телепортується/твінується всередину "тіла" клітини, яка сама рендериться як величезна мікроскопічна арена.
- Куля гравця також масштабується (0.3× розмір, 0.3× швидкість) в мікро-світі — масштаб є наскрізним, а не косметичним.
- Перехід супроводжується DOTween-анімацією (масштаб, поворот і позиція камери), зміною шару фізики (`InsideCellPlayer`), зміною аудіо-міксера (окремий `InCellMixer`) і зміною спрайту клітини (здорова/хвора текстура).

Це і є суть "Built to Scale": та сама клітина, яка ззовні виглядає як маленьке коло, зсередини — величезна арена; та сама вхідна дія гравця (WASD) рухає його на різних відносних швидкостях залежно від масштабу світу.

## 3. Основний ігровий цикл

1. Літати макро-світом (інерційний "дрейф", не Unity-фізика), стріляти/уникати вірусів, що женуться до клітин.
2. Коли макро-вірус проникає в клітину — клітина "хворіє" (візуальна десатурація через шейдер), втрачає здоров'я щосекунди пропорційно кількості вірусів усередині.
3. Гравець може підійти до хворої клітини й натиснути **E** → зменшитись і потрапити всередину клітини на бій із внутрішньоклітинними вірусами.
4. Знищити всіх вірусів усередині → клітина повністю виліковується (здоров'я = 100).
5. Якщо здоров'я клітини впаде до 0 раніше — клітина гине (вибух), і на її місці спавняться `virusCount + 1` нових макро-вірусів — невдача погіршує спалах. Якщо гравець у цей момент був усередині клітини — його примусово викидає в макро-світ.
6. Вбивство вірусів і збирання/розбиття "пігулок" (`Medical` → розсипаються вітамінами, що летять до гравця) дає досвід.
7. Набір рівня → пауза, вибір 1 з 3 випадкових апгрейдів.
8. Цикл повторюється з ескалацією (більше вірусів, нові типи ворогів з часом), доки гравець не помре або не загинуть усі клітини.

**Умова поразки:** здоров'я гравця ≤ 0, або всі клітини мертві (`CellManager.Pool.Count == 0`).
**Умова перемоги:** відсутня в коді — гра є **нескінченним survival/score-attack** режимом (виживання якнайдовше), а не рівнем з завершенням. Це варто явно зафіксувати як усвідомлений дизайн (або як недороблену фічу через обмеження 96 годин).

Рестарт: будь-яка клавіша на екрані Game Over → фейд → повернення в меню (сцена 0).

## 4. Гравець

### 4.1 Керування

| Дія | Клавіша/пристрій |
|---|---|
| Рух корпусу | WASD (композит; у файлі `.inputactions` W/S/A/D прив'язані як up/down/**right/left відповідно, тобто A/D інвертовані** — ймовірно артефакт поспіху джему) |
| Наведення турелі | Позиція курсора миші (twin-stick, незалежно від напрямку корпусу) |
| Постріл | ЛКМ |
| Увійти/вийти з клітини | E |
| Рестарт після смерті | Будь-яка клавіша |

### 4.2 Механіки корпусу

- Інерційний рух ("дрейф") власної реалізації (`DriftMovableObject`): прискорення, тертя, кутове тертя — не стандартна Rigidbody2D-фізика (Rigidbody2D velocity обнуляється щокадру).
- Рух заднім ходом уповільнений до 5% швидкості.
- Турель наводиться незалежно від корпусу (twin-stick shooter).
- Перезарядка турелі — кулдаун з радіальним UI-індикатором.

### 4.3 Здоров'я і броня

- Базове здоров'я — 3 (жорстко закодоване значення при старті; серіалізоване поле `_maxHealth` використовується лише як стеля для апгрейду, не як стартове значення — ймовірна неузгодженість).
- Броня (0–8): шанс `Armor / 6.0` повністю ігнорувати урон, витрачаючи 1 одиницю броні.
- Смерть → анімація → через 2с показ екрана Game Over.

### 4.4 Локатор ворогів

Стрілка на екрані вказує на найближчого активного вірусу (або найближчу хвору клітину, якщо вірусів немає) — тільки в макро-світі, і тільки коли ціль поза межами видимості камери.

## 5. Прогресія (RPG-lite)

- Досвід → рівень; крива вимоги XP — ×1.5 за кожен рівень (стартова вимога — 3 XP).
- Джерела досвіду: вбивство вірусів (макро й мікро), збір вітамінів з пігулок.
- На кожен level-up гра ставиться на паузу (приховуються бари), пропонується **3 випадкові апгрейди з 6 можливих типів**:

| Апгрейд | Ефект |
|---|---|
| PLAYER_MOVE_SPEED | Швидкість руху корпусу |
| PLAYER_MOBILITY | Маневреність (поворот) |
| PLAYER_ATTACK_SPEED | Швидкість перезарядки турелі |
| PLAYER_ARMOR | Броня (шанс ігнорувати урон) |
| PLAYER_DAMAGE | Урон кулі |
| PLAYER_HP | Максимальне здоров'я |

- Прихована механіка: **кожен парний рівень автоматично додає +1 HP** незалежно від обраного апгрейду (закладено в код обробки апгрейду, ніде не задокументовано в UI).

## 6. Вороги

### 6.1 Макро-віруси (вільно літають, полюють на клітини)

Поведінка через стратегію (3 стани):
1. **MoveToCell** — рухається до найближчої живої клітини.
2. **AttackCell** — торкнувшись клітини, кружляє/таранить її.
3. **PenetrationIntoCell** — після затримки зменшується (DOTween) і "проникає" в клітину, заражаючи її.

Через ~80 секунд гри розблоковується додатковий, важчий тип ворога (`_glistPrefab`, текстури "PinkGlist"/"BigBob") — часовий гейт складності.

Спавн хвилями по колу навколо центру мапи; нова хвиля стартує, коли попередня знищена і менше 2 клітин заражені; розмір хвилі зростає ×1.5 щоразу.

### 6.2 Внутрішньоклітинні віруси (бій усередині клітини)

Три типи, з ґейтом за часом гри:

| Тип | Розблокування | Поведінка |
|---|---|---|
| **Orange** | Завжди доступний | Найпростіший — суцільний рух до гравця (наведення силою), лише ближній бій |
| **Cucumber** | Час ≥ 50с | Наведення + дальня атака (снаряд), кулдаун ~2с |
| **Spiner** | Час ≥ 100с | Періодичний фізичний ривок ("спін-раш") у бік гравця з розгоном, кулдаун 4с |

Позиції вірусів усередині клітини рандомізуються при кожному вході.

### 6.3 Лор-описи (з readme, promo-матеріал)

- **Virus Invader** — "Маленькі та швидкі, ці вороги намагаються заразити здорові клітини."
- **Giant Virus** — "Масивні, з огидними м'ясистими тілами й численними щупальцями."
- **Mutated Virus** — "Ці віруси зазнали небезпечних генетичних мутацій. Їхня атака — обертання й ривок на гравця, що завдає шкоди." (відповідає поведінці **Spiner**)
- **Warrior Virus** — "Мобільні патогени, що можуть об'єднуватись для скоординованих атак. Вивільняють токсини або атакують зграями." — **ця поведінка (координація/зграя) не знайдена в коді**, ймовірно недороблена/задекларована лише в промо-описі фіча, вирізана через дедлайн джему.

## 7. Клітини

- Приховане здоров'я (стартує зі 100), падає на `virusCount` HP/сек, поки заражена.
- Шейдерний параметр `_Blend` твіниться пропорційно здоров'ю — візуальна "хворобливість" спрайту.
- Одужання (health → 100) при знищенні останнього внутрішнього вірусу.
- Смерть клітини (health = 0) → вибух через 2с затримки, спавн нових вірусів = `virusCount + 1` у місці загибелі — карається ескалацією.
- Клітини й "пігулки" (Medical) та фонові бактерії розміщуються процедурно на старті рівня (rejection-sampling з мінімальною дистанцією) — рівень щоразу трохи інший, але без ручного дизайну арени.

## 8. Рівні / структура сцен

Гра має лише **дві сцени**:

1. **Menu** — головне меню з коротким Timeline-катсценою (PlayableDirector) при натисканні Play, кнопки Play/Exit.
2. **SampleScene** — єдина ігрова арена (прямокутна, обмежена 4 бар'єрами), увесь контент (клітини, віруси, пігулки, фонові бактерії) спавниться процедурно при старті.

Прогресії рівнів, вибору рівня чи відмінностей контенту між "рівнями" немає — гра є одноарзонним нескінченним режимом.

## 9. UI/HUD

- Бари здоров'я, броні, досвіду (заповнення, анімоване DOTween).
- Таймер гри (MM:SS) — керує всіма часовими розблокуваннями складності.
- Статистика: кількість живих/хворих/загиблих клітин.
- Контекстна підказка "увійти/вийти з клітини" біля хворих клітин.
- Екран вибору апгрейду (3 картки).
- Екран Game Over (текст залежить від причини поразки — смерть гравця чи загибель усіх клітин).
- Шрифт — тільки Comic Sans MS (плейсхолдер джему, потребує заміни для повноцінного релізу).

## 10. Аудіо

- 2 музичні треки (інтро-меню + основний геймплейний), кросфейд між сценами.
- 14 звукових ефектів (вибух, смерть клітини/вірусів, влучання, лікування, level-up, атаки тощо).
- 2 аудіо-міксери — окремий мікс для мікро-світу (`InCellMixer`) створює відчуття "заглушеності зсередини клітини".

## 11. Відомі прогалини дизайну (для розділу "Known Issues" при рефакторингу)

- Немає умови перемоги/завершення — тільки нескінченне виживання.
- "Warrior Virus" зі зграйною поведінкою — заявлена, але не реалізована фіча.
- Інвертоване A/D керування в `.inputactions` — ймовірний баг, не навмисний дизайн.
- Стартове здоров'я гравця (3) не пов'язане з серіалізованим `_maxHealth` — неузгодженість намірів.
- Немає прогресії рівнів/змісту — весь геймплей це один процедурний майданчик по колу зростаючої складності.
